# Лабораторные работы 1–5 по машинному обучению

## 1. Состав проекта

В проекте должны находиться три основных файла:

- `README.md` — постановка задач, данные, метрики, гипотезы, порядок запуска и интерпретация результатов;
- `laboratories_1_5.ipynb` — единый Jupyter Notebook с пятью лабораторными работами и поясняющими комментариями в каждой кодовой ячейке;
- `final_comparison.ipynb` — отдельный Jupyter Notebook с итоговым рейтингом и сравнением алгоритмов ЛР1–ЛР5.

Основной ноутбук также формирует папку `results/` с таблицами, JSON-аудитом и графиками, которые использует итоговый ноутбук.

## 2. Данные и практическая задача

**Digits — `sklearn.datasets.load_digits`.** Каждый объект представлен 64 значениями яркости пикселей изображения 8×8; требуется классифицировать изображение как одну из цифр 0–9. Это учебный аналог распознавания рукописных цифр (OCR) и автоматизации ввода документов.

**Diabetes — именно `sklearn.datasets.load_diabetes`.** Это задача регрессии количественного показателя прогрессирования заболевания по 10 количественным признакам. Это не бинарная диагностика. Практическая интерпретация — прогноз количественного показателя для исследовательской/аналитической поддержки.


## 3. Метрики и экспериментальный протокол

Для классификации используются Accuracy, macro-Precision, macro-Recall и macro-F1. Accuracy показывает общую долю верных ответов; macro-метрики одинаково взвешивают каждый класс, поэтому качество на отдельных цифрах не скрывается за частыми классами. Основной критерий — максимальный macro-F1.

Для регрессии используются MAE, RMSE и R². MAE измеряет среднюю абсолютную ошибку в единицах целевой переменной; RMSE сильнее штрафует крупные ошибки; R² показывает долю объяснённой вариации относительно прогноза среднего. Основной критерий — минимальный RMSE, дополнительно анализируются MAE и R².

Все работы используют единое разбиение 80/20 с `random_state=42`; для Digits применяется стратификация. GridSearchCV использует 5-fold CV только на обучающей части. Препроцессинг в KNN/линейных моделях включён в Pipeline, чтобы масштабирование не подглядывало в CV-валидационные или тестовые данные. Итоговые метрики рассчитаны на одной фиксированной тестовой выборке.

## 4. Гипотезы

- **H1 — масштабирование KNN.** Проверяется, изменит ли стандартизация качество KNN для Digits и Diabetes. Гипотеза проверяется отдельно для каждой задачи.
- **H2 — новые признаки.** Для Digits добавляются `pixel_mean`, `pixel_std`, `active_pixels`; для Diabetes — `bmi_bp_interaction`, `bmi_squared`, `s5_squared`.
- **H3 — настройка параметров.** В ЛР3 подбираются глубина и размер листа дерева; в ЛР4 — число деревьев, глубина и размер листа леса; в ЛР5 — число итераций, скорость обучения и сложность базовых деревьев.
- **H4 — ансамбли.** Сравниваются tuned-дерево и tuned-лес. Улучшение оценивается по macro-F1 для классификации и RMSE для регрессии; устойчивость на разных разбиениях отдельно не измеряется.

Гипотеза считается поддержанной только при улучшении целевой метрики на отложенной выборке. Рост RMSE, снижение macro-F1 или R² не называются улучшением.

## 5. Что выполнено в каждой лабораторной

- **ЛР1 — KNN.** Baseline для классификации и регрессии, проверка стандартизации, подбор числа соседей, собственные `MyKNNClassifier` и `MyKNNRegressor`, а также `custom_improved` с выбранным `k` и масштабированием.
- **ЛР2 — логистическая и линейная регрессия.** LogisticRegression и LinearRegression/Ridge, собственные softmax- и линейная реализации, проверка feature engineering и повторное обучение собственных моделей с новыми признаками.
- **ЛР3 — решающее дерево.** Baseline, GridSearchCV для глубины и минимального размера листа, собственная CART-реализация, `custom_improved` с выбранными ограничениями сложности.
- **ЛР4 — случайный лес.** Baseline, настройка числа деревьев/глубины/размера листа, сравнение с одиночным деревом, feature importance, собственный bootstrap-лес и улучшенная собственная версия.
- **ЛР5 — градиентный бустинг.** Baseline и tuned sklearn-модели гистограммного градиентного бустинга, собственная реализация последовательного бустинга остатков/градиентов и `custom_improved` с подобранной скоростью обучения и приближённой глубиной дерева.

В собственной реализации CART ограничен поиск признаков и порогов. Для собственного случайного леса `custom_improved` число деревьев ограничено 30, глубина — восемью уровнями; для собственного бустинга оставлено 15 итераций, а параметры скорости обучения и глубины переносятся из CV в приближённом виде. Эти ограничения явно учитываются при сравнении со sklearn.

Стадии не полностью одинаковы по смыслу в каждой работе:

| Лабораторная | Reference-стадия улучшения |
|---|---|
| ЛР1 | `improved_sklearn` — выбранное k + стандартизация |
| ЛР2 | `feature_engineered` — sklearn-модель с новыми признаками |
| ЛР3 | `tuned` — дерево после GridSearchCV |
| ЛР4 | `tuned` — лес после GridSearchCV |
| ЛР5 | `tuned` — HistGradientBoosting после GridSearchCV |

Для всех пяти работ присутствуют `baseline`, `custom` и `custom_improved`. Этап `custom_improved` сравнивается не обязательно с одноимённым `tuned`: таблица содержит колонку `reference_stage`, указывающую реальную стадию улучшенного sklearn-варианта.

## 6. Порядок запуска

1. Откройте `laboratories_1_5.ipynb` и выполните все ячейки сверху вниз. Последняя ячейка сформирует `results/`.
2. Затем откройте `final_comparison.ipynb` и также выполните ячейки сверху вниз. Он загрузит сохранённые таблицы и построит итоговые рейтинги.

Для запуска необходимы Python, Jupyter, NumPy, pandas, Matplotlib и scikit-learn.

## 7. Сохраняемые результаты

Основные артефакты:

- `results/metrics.csv` — метрики всех стадий всех лабораторных;
- `results/baseline_vs_tuned.csv` — baseline против reference-стадии улучшения;
- `results/custom_vs_baseline.csv` — собственная исходная реализация против sklearn-baseline;
- `results/custom_improved_vs_tuned.csv` — улучшенная собственная реализация против reference sklearn-модели с указанием `reference_stage`;
- `results/best_params.json` — лучшие параметры GridSearchCV;
- `results/audit.json` — размеры выборок, лучшие модели и результаты проверки гипотез;
- `results/feature_importance.csv` — важности признаков случайного леса;
- `results/figures/` — распределение классов, матрица ошибок лучшего классификатора, график фактических/предсказанных значений лучшего регрессора, кривая loss softmax-модели и график feature importance.

## 8. Содержательные выводы по текущему разбиению

Для Digits лучший sklearn-результат дал KNN без масштабирования: macro-F1 **0.9830**. Стандартизация уменьшила macro-F1 до **0.9634**, поэтому H1 для классификации не подтвердилась. Для Diabetes стандартизация немного снизила RMSE KNN с 54.653 до 54.493, хотя MAE незначительно вырос; эффект небольшой.

Новые признаки в ЛР2 поддержали H2 по обеим задачам: macro-F1 логистической регрессии вырос с 0.9581 до 0.9804, RMSE Ridge снизился с 53.853 до 52.654, R² вырос с 0.4526 до 0.4767. Собственная линейная регрессия с теми же новыми признаками показала RMSE 51.892 и R² 0.4918 на этом разбиении.

Настройка дерева в ЛР3 не изменила macro-F1 (0.8230), но снизила RMSE регрессии с 70.546 до 59.605. В ЛР4 настройка леса не улучшила метрики относительно baseline; при этом tuned-лес превосходил tuned-дерево по macro-F1 и RMSE на текущем split. В ЛР5 настройка HistGradientBoosting улучшила регрессию (RMSE 57.029 → 53.062; R² 0.3861 → 0.4686), но немного снизила macro-F1 классификации (0.9547 → 0.9522).

Среди sklearn-регрессоров лучший RMSE дал Ridge с новыми признаками в ЛР2 (**52.654**); среди собственных реализаций лучший RMSE у MyLinearRegression с новыми признаками (**51.892**). Для классификации общий лидер — KNN без масштабирования. Таким образом, лучший алгоритм зависит от задачи, а настройка гиперпараметров не гарантирует улучшения по всем метрикам.

Все результаты относятся к одному фиксированному разбиению.
